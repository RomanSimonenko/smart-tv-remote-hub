# БЛЮДЦЕ lab

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Основной пользователь — тестировщик Smart TV, работающий в настольном браузере.

## Product Purpose

Рабочий инструмент для управления телевизорами, подготовки тест-кейсов, выполнения тестов и просмотра результатов. Интерфейс должен помогать выполнить эти задачи и понимать текущее состояние устройства и запуска.

## Operating Context

Этот документ относится к веб-интерфейсу `apps/web`. Сервер и платформенные адаптеры находятся в соседних пакетах репозитория. Основной рабочий контекст — настольный браузер; изображение камеры служит визуальным свидетельством состояния физического экрана.

## Capabilities and Constraints

- Минимальная поддерживаемая ширина рабочей области браузера определена в разделе 7 [ТЗ интерфейса](../../docs/superpowers/specs/2026-10-11-product-ui-design.md); применять её при реализации и визуальной приёмке.
- Основные пользовательские области: обзор, телевизоры, тест-кейсы, запуски и настройки.
- Согласованный сценарий использования не доказывает готовность функции: фактические возможности проверяются по текущему коду и работающему приложению.
- Доставка команды телевизору не является подтверждением результата на физическом экране.
- Изменения интерфейса должны сохранять контракты API, авторизацию и пользовательские данные.

## Brand Commitments

Название продукта — «БЛЮДЦЕ lab». Рабочий интерфейс использует понятные русские подписи и спокойную инструментальную подачу. Существующий согласованный дизайн сохраняется.

## Product Principles

1. Последующие явно согласованные требования имеют приоритет над ТЗ; ТЗ имеет приоритет над макетами. Этот документ не создаёт конкурирующей дизайн-спецификации.
2. Сохранять общую систему интерфейса и использовать существующие общие токены и компоненты.
3. Подтверждать выводы о внешнем виде скриншотами работающего приложения; функциональные тесты сами по себе не подтверждают визуальное соответствие.
4. После изменений UI проверять активное приложение пользователя по правилам проекта, сохраняя данные и несохранённые правки.

## Open Decisions

Специальные требования доступности и дополнительные аудитории отдельно не подтверждены. Не приписывать продукту неподтверждённые стандарты, возможности или эксплуатационные гарантии.
