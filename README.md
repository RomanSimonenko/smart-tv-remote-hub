# БЛЮДЦЕ lab

Self-hosted веб-приложение для управления и тестирования Smart TV из браузера.

Приложение объединяет виртуальный пульт, внешнюю камеру, редактор тест-кейсов и запуск проверок с сохранением снимков. Поддерживаются несколько телевизоров **LG webOS, Samsung Tizen и Philips Whale OS** и один аккаунт владельца.

## Возможности

### Телевизоры и пульт

- Дашборд устройств, добавление по локальному IPv4-адресу, сопряжение, переподключение и настройки каждого ТВ.
- Навигация, цифровые и цветные кнопки, громкость и каналы. Управление мышью и клавиатурой; удержание и повтор нажатий зависят от платформы и доступных возможностей ТВ.
- Информация о модели и известной версии ОС. Недоступные действия блокируются в интерфейсе.
- При потере связи с сервером показывается общее сообщение; предупреждения о неопределённом результате команды сохраняются отдельно.

| Платформа | Подключение | Возможности и ограничения |
| --- | --- | --- |
| LG webOS | SSAP через WebSocket, отдельный сокет нажатий | Пульт, запуск Wink, выключение и Wake-on-LAN. Для включения по сети нужен MAC активного подключения. |
| Samsung Tizen | WSS на порту 8002; HTTP API на 8001 для состояния | Пульт, включение из standby и выключение с проверкой состояния. MAC и WOL не используются. Запуск Wink и каталог приложений пока недоступны. |
| Philips Whale OS | jointSPACE v6 через HTTPS на порту 1926, HTTP Digest | Сопряжение по PIN с экрана ТВ, сохранение ключей, переподключение и базовый пульт. Питание, запуск приложений, ввод текста, указатель и нативное удержание пока не поддерживаются. |

Совместимость зависит от модели, прошивки и настроек ТВ. Доставка команды не доказывает её физический результат на экране.

### Камера и распознавание текста

- Просмотр внешней камеры, выбор устройства и разрешения HD / Full HD.
- Автоматический поиск границ ТВ и выравнивание перспективы. При недостаточных или неоднозначных границах приложение сообщает «Экран не найден».
- Пробное распознавание текста на свежем выровненном снимке: изображение, его разрешение, распознанный текст и время OCR. Сворачивание панели не отменяет запрос; процесс обозначается анимированным спиннером. Проба не создаёт запись в истории запусков.
- Запись исходного видео камеры без звука: остановка со скачиванием или отмена без сохранения файла. Имя файла содержит модель ТВ. Ограничения — 5 минут или 128 МБ; при достижении лимита запись завершается автоматически. Выбор папки сохранения пока не реализован.

Изображение поступает с камеры, подключённой к браузеру, а не из видеопотока самого телевизора. Для OCR снимок передаётся серверу приложения и обрабатывается локальным Python-процессом, без внешнего облачного OCR-сервиса.

### Тест-кейсы и запуски

- Редактор единой последовательности шагов «Дано», «Когда», «Тогда»: вставка, перемещение, перетаскивание и дублирование шагов.
- Настройка последовательностей нажатий, пауз после действий и искомых надписей.
- BDD-импорт из текста или `.js` / `.ts` с предпросмотром черновика; импортируемый код не выполняется.
- Последовательное выполнение: команда → подтверждение доставки → пауза → свежий снимок → сохранение → проверка текста, если она задана.
- Прогресс в реальном времени: галочки завершённых шагов и анимированный индикатор текущего действия. Шаг с текстовыми условиями получает успешный статус только после их проверки.
- Остановка запуска, история, отчёты и сохранённые снимки. Все текстовые условия шага должны находиться на одном кадре. Несовпадение текста отличается от технической ошибки; шаги без автоматических условий требуют оценки пользователем.

Автоматическое сравнение изображения с эталоном пока не реализовано. Поиск границ экрана сам по себе не подтверждает правильность изображения.

## Запуск

Нужен Docker с Compose; на macOS можно использовать Docker Desktop. Сервер должен иметь сетевой доступ к телевизорам. Из корня репозитория:

```sh
docker compose up -d --build
docker compose exec app node apps/api/dist/src/auth/cli.js setup-token
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080), введите одноразовый токен и создайте аккаунт. Токен нужен только для первоначального создания владельца.

На дашборде «Телевизоры» выберите платформу, добавьте включённый ТВ по частному IPv4-адресу и выполните сопряжение. Для LG и Samsung подтвердите доступ на телевизоре; для Philips введите показанный на ТВ PIN в приложении. Карточка устройства открывает пульт и камеру.

Для запуска кейса откройте раздел «Тест-кейсы», подготовьте шаги, выберите ТВ и включите камеру. Дождитесь подтверждения границ экрана перед началом.

Смена порта, настройка WOL, обновление и резервная копия: [инструкция Docker](docs/docker-desktop.md).

## Важно

- Сервер должен иметь доступ к локальной сети ТВ. Удалённый сервер сам по себе не обеспечивает управление домашним ТВ и WOL.
- Во время выполнения кейса вкладка запуска должна оставаться открытой: она управляет получением кадров и последовательностью действий. Потеря связи, закрытие вкладки или перезапуск сервера останавливают запуск; автоматического продолжения нет.
- При добавлении LG укажите MAC активного подключения (Wi-Fi или кабель). Он сохраняется вместе с конкретным ТВ; переподключение, смена IP и обновление данных модели его не заменяют. Изменить или очистить MAC можно только вручную в настройках выбранного ТВ. Для старых API-клиентов поле при добавлении остаётся необязательным: без ручного MAC включение по сети недоступно. Отправка команды не гарантирует её физический результат.
- Не публикуйте хранилище аккаунта, ключей и резервные копии. Для обновления не используйте `docker compose down -v`: это удаляет данные.
- По умолчанию приложение доступно только на компьютере запуска. Для доступа извне нужен отдельно настроенный HTTPS и защита сети.
- Совместимость зависит от модели ТВ. При отозванном ключе возможен запрос доступа на экране даже при восстановлении связи.
- Samsung подключается к локальному HTTP API на 8001 и WSS на 8002. Самоподписанный сертификат принимается только этим Samsung-соединением; глобальная проверка TLS не отключается, перехода на WS нет. Это не удостоверяет личность ТВ и не защищает от подмены устройства в локальной сети. Отозванный Samsung-токен требует явного повторного сопряжения и подтверждения на ТВ.
- Устройства, аккаунт, тест-кейсы, история и снимки хранятся в постоянном Docker volume. Учётные данные сопряжения шифруются. Перед миграцией SQLite создаётся резервная копия; для отката нужны совместимая копия всего каталога данных и прежняя версия сервера. Автоматического понижения схемы нет.
- Последний выход из аккаунта закрывает соединения с ТВ, сохраняя устройства и авторизацию. После нового входа выберите «Подключиться снова» в настройках ТВ. Выход одной сессии не прерывает соединения другой действующей сессии.

Текущая поставка — локальное self-hosted приложение. Вариант с размещённым веб-сервисом и отдельным локальным агентом описан в [концепции](docs/superpowers/specs/2026-10-19-web-service-local-agent-concept.md), но ещё не реализован.

## Технологии и разработка

Монорепозиторий на TypeScript с pnpm workspaces:

- `apps/web` — React 19, Vite 7, CSS и Tabler Icons.
- `apps/api` — Node.js, Fastify 5, SQLite через `better-sqlite3`.
- `packages/contracts` — общие типы и схемы валидации Zod.
- `packages/tv-adapter`, `packages/webos`, `packages/tizen`, `packages/philips` — общий контракт и платформенные адаптеры.
- `packages/screen-vision` — OpenCV.js и Sharp для поиска экрана и выравнивания.
- OCR — Python, PaddleOCR и PaddlePaddle; зависимости и модели включаются в Docker-образ.
- Тесты — Vitest, React Testing Library и Playwright с синтетическими телевизорами; CI — GitHub Actions.

Для разработки используйте Node.js 24 и pnpm 11.15.1. Основные команды из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm test
pnpm --filter @remote-webos-tv/web test:e2e
```

Настройка окружения, OCR и браузерных тестов: [инструкция для разработки](docs/development.md).
