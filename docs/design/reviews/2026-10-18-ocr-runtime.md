# Выбор локального OCR для условий шага

Дата: 2026-10-18. Проверка только на синтетических экранах, без камеры и команд ТВ.

## PaddleOCR

Изолированный Docker ARM64: PaddleOCR 3.2.0, PaddlePaddle 3.2.0,
PP-OCRv5_server_det и eslav_PP-OCRv5_mobile_rec. ARM64 wheel доступен,
образ собирается и модели загружаются. При офлайн-распознавании положительного
синтетического кадра процесс завершается SIGSEGV (exit 139). Повтор с
`enable_mkldnn=False` даёт тот же результат. Модель явно выбиралась по её имени;
до этого проверка выявила несовпадение имени и каталога модели.

Для текущей реализации PaddleOCR не выбран: рабочее распознавание в целевом
контейнере не подтверждено. Исследовательский Dockerfile сохранён отдельно;
в продуктовый образ PaddleOCR не входит.

## Tesseract

Выбран существующий в проекте tesseract.js 7.0.0 с пакетами языковых моделей
rus/eng 1.0.0 (данные 4.0.0). Модели устанавливаются при сборке; во время OCR
используются локальные файлы. Один дочерний процесс на кадр, тайм-аут 30 секунд,
без повторов и без автоматического переключения на другой движок.

Набор: тёмные JPEG 1280×720, шрифт Noto Sans 40 px, надписи «Мое кино»,
«Мои подписки», «Settings». Проверены: все три надписи, одна русская отсутствует,
обе русские отсутствуют, пустой кадр, слова «Мое»/«кино» в разных областях,
повреждённый JPEG. Ожидаемые результаты получены для всех шести случаев при
локальном запуске и в ARM64-образе приложения с `--network none`. Раздельные слова не дали ложного совпадения «Мое кино».

Это проверка интеграции и простого синтетического набора, а не оценка точности
на реальных кадрах камеры. Пользовательские шрифты, блики, размытие и мелкие
надписи требуют отдельной аппаратной приёмки. Отсутствие распознанной надписи
даёт отрицательный результат условия по согласованному контракту.

Воспроизведение после сборки:

```sh
node tools/visual-checks-probe/ocr-runtime/fixtures.mjs .local/ocr-fixtures
node tools/visual-checks-probe/ocr-runtime/check-tesseract.mjs .local/ocr-fixtures
```
