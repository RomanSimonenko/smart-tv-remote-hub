# Проверка OCR и сравнения с эталоном

Дата: 2026-10-14. Первый локальный технологический эксперимент, без управления ТВ.

Дополнение: [сравнение OCR на реальном кадре телефона](camera-comparison.md).

Подготовка изображения: [20 областей на двух экранах LG](camera-preprocessing.md).

Последний этап: [проверка на новом английском экране](camera-english-validation.md).

## Результат

Подход работает на контрольных синтетических изображениях. Tesseract.js остаётся
кандидатом для следующего этапа, OpenCV — кандидатом для сравнения эталонов.
Выбор для рабочего запуска ещё не завершён: нужны реальные кадры камеры,
нормализация экрана и проверка пригодности изображения.

Исходные материалы, значения и разметка: [HTML-отчёт](report/index.html),
[JSON-отчёт](report/report.json), [скриншот отчёта](ocr-report.png).
Все изображения синтетические; опубликованных пользовательских сценариев нет.

| Проверка | Наблюдение |
|---|---|
| Русский: «Программа передач», «Каталог» | Обе строки распознаны |
| Английский: «Settings» | Строка распознана |
| Другая надпись и пустая область | Ожидаемая строка не найдена |
| Мелкий шрифт | Найдена подстрока, но OCR добавил точку; точное равенство было бы неверным |
| Размытие, затемнение, перспективное искажение | Ожидаемая подстрока найдена в этих конкретных образцах |
| Сильный блик | Текст не распознан; это не доказывает его отсутствие |
| Карточка с фокусом | Корреляция с эталоном ≈1,000 |
| Карточка без фокуса | Корреляция ≈0,326 |
| Та же карточка с размытием | Корреляция ≈0,937; экспериментальный порог 0,95 не пройден |

На 13 кадрах OCR занимал 188–324 мс на кадр, сравнение эталонов — 9–14 мс.
Это разовые локальные измерения с запуском отдельного OCR-процесса, а не SLA
или оценка скорости будущего браузерного раннера.

## Ограничения и решение

- Набор мал, надписи простые: проценты «точности» на реальном ТВ из него не выводим.
- Камерный шум, изменение масштаба и перспективы для эталонов пока не компенсируются.
- Порог 0,95 — параметр эксперимента, не утверждённое продуктовое значение.
- `notContains` возвращает неопределённость до проверки качества кадра.
- OCR confidence не используется как доказательство резкости или отсутствия текста.
- `not-matched` в этом отчёте — результат сравнения, не провал реального тест-кейса.
- Эталон в продукте будет сохраняться пользователем из нужного состояния ТВ.
  Синтетический эталон используется только для исследования алгоритма.

Следующий этап: получить репрезентативные реальные кадры с согласия пользователя,
проверить автоматическое обнаружение/нормализацию экрана и определить критерии
пригодности. Затем подготовить макеты настройки проверок и ТЗ интеграции.

## Проверки реализации

- 21 тест пакета: повторяемость кадров, точное сравнение, отрицательная проверка,
  реальный OCR и координаты, отмена/ошибки/очистка worker, поиск эталона и области,
  оригиналы, защита путей, повторный запуск, отмена CLI.
- Общий набор: 1499 тестов прошли, включая 21 новый. Повторный эксперимент дал
  те же наблюдения. Проверены typecheck и сборка проекта; тесты запускались с разрешением
  локальных тестовых сокетов. Первоначальный запуск в sandbox падал на `EPERM`
  в существующих тестах webOS, а не на новом эксперименте.
- Отчёт просмотрен в браузере: рамки совпадают с распознанными словами,
  исходный кадр остаётся отдельным файлом. Приложение и Docker не изменялись.

## Принятые технические решения

- Работа в текущем checkout на отдельной ветке сохраняет согласованные документы
  вместе с экспериментом. При необходимости ветку можно перенести в worktree.
- Добавлен `tools/*` в workspace; это делает отдельный пакет доступным командам
  проекта, но не добавляет OCR в зависимости веб-приложения.
- Закреплённый Noto Sans преобразуется в SVG-контуры через fontkit: это устраняет
  зависимость кадров от системных шрифтов. При проблемах меняется только генератор.
- OCR запускается в отдельном процессе для гарантированной отмены, включая фазу
  инициализации Tesseract. Цена — старт процесса на каждый кадр, включённый в замер.
- OpenCV загружается через Node CommonJS promise: так сохраняется корректная
  инициализация WASM. Для будущей браузерной интеграции нужен отдельный загрузчик.

Ревью выявило обход очистки при сигнале остановки CLI. Регрессионный тест сначала
получил код 0 вместо 130; после исправления SIGINT/SIGTERM передаются в OCR,
и CLI дожидается освобождения ресурсов. Незначительных отложенных замечаний нет.
