# Импорт одного BDD-тест-кейса

Статус: согласовано пользователем; первый этап реализован. Дата: 2026-10-13.

## Цель

Перенести описательные шаги из фрагмента `given / when / then / .and` в
существующий редактор. Сохранение использует текущий API черновиков.
Реальные сценарии и импортированные файлы не добавляются в репозиторий приложения.

## Первый этап

В списке тест-кейсов появляется вторичная кнопка «Импортировать» рядом с
«Создать тест-кейс». Она открывает диалог в текущем визуальном стиле приложения.
Пользователь вставляет фрагмент или выбирает локальный текстовый файл .js/.ts.
Оба способа заполняют одно поле исходного текста; выбор файла не запускает импорт.
При замене уже введённого текста требуется подтверждение его потери.

Название извлекается из обёртки сценария после проверки, если поле пустое или ещё содержит прошлое автоматически извлечённое название. Пользователь может изменить его; введённое вручную название не перезаписывается. Для фрагмента без обёртки название задаёт пользователь. После «Проверить» показывается предпросмотр:
блоки «Дано / Когда / Тогда», тексты и количество шагов. Ошибка содержит понятную
причину и позицию в тексте, но не копирует содержимое сценария в журналы.
Изменение исходного текста сбрасывает устаревший предпросмотр.

«Открыть в редакторе» доступно после успешной проверки и ввода корректного названия.
Оно создаёт только локальный несохранённый черновик со свежими UUID кейса и шагов.
Дальнейшие изменения и запись выполняются существующими кнопками редактора.
Закрытие диалога с введёнными данными требует подтверждения. Существующие кейсы
не перезаписываются; серверная запись возможна только через «Сохранить тест-кейс».

## Поддерживаемый синтаксис

Один фрагмент с последовательностью выражений `given('…')`, `when('…')`,
`then('…')` и их цепочками `.and('…')`; допускаются `await`, комментарии,
переносы строк и точки с запятой. Строки — литералы в одинарных или двойных
кавычках с обычными escape-последовательностями JavaScript.

`.and` наследует блок корневого вызова своей цепочки. Исходный порядок всех шагов
сохраняется, включая given → when → then → when → then. Повторение типов
и пропуск блока разрешены для черновика. Пустой фрагмент отклоняется.

Поддерживается одна обёртка `scenario`, `scenario.manual`, `scenario.skip` или `scenario.manual.skip`: строковое название и inline-функция без параметров с блоком шагов. Модификаторы не влияют на импорт описания. Второй аргумент шага — inline arrow/function без параметров — пропускается без выполнения и без извлечения вложенных шагов или комментариев. Предпросмотр явно сообщает число пропущенных функций.

Переменные, выражения, интерполяция, ссылки на функции, другие обёртки (включая `test`),
импорты модулей и произвольные операторы отклоняются явно. Неподдерживаемые части
не пропускаются молча. Импорт целых файлов с несколькими кейсами и синхронизация
с приватным Git-репозиторием остаются следующими самостоятельными этапами.

## Границы и реализация

Разбор выполняется в браузере синтаксическим парсером и проверкой разрешённых
узлов; `eval`, `Function`, выполнение модулей или сценариев запрещены.
Извлекаются только строковые значения, тип блока и порядок. Исходник и файл
не отправляются на сервер и не сохраняются в браузерное постоянное хранилище.
На сервер при явном сохранении отправляется обычный валидированный черновик.

Лимит файла/исходника — 64 КиБ UTF-8. Общие контракты черновика остаются источником
ограничений названия, числа шагов и длины текста. На первом этапе импорт не
назначает команды пульта, проверки изображения и готовность к выполнению.

Новые компоненты используют существующие диалоги, кнопки, иконки и токены из
продуктового дизайн-ТЗ. Светлая тема и перевод RU/EN остаются финальным этапом.

## Проверка

Синтетические примеры: цепочки и переносы, кавычки и escape-последовательности,
комментарии, отсутствующий блок, повторные пары when/then, отдельный `.and`, произвольный
код, переменные и обработчики, пустой/слишком большой файл, предельные шаги и
тексты. Неподдерживаемый код не исполняется и не создаёт частичный импорт.

UI: вставка и выбор файла, замена текста, инвалидирование предпросмотра,
ошибки без потери ввода, закрытие с подтверждением, переход в редактор,
сохранение и повторное открытие. Проверить клавиатуру, фокус диалога и узкое окно.
Перед сдачей обновить Docker и визуально проверить реальный интерфейс на 8081.

## Реализованный этап

Импорт одного фрагмента через текст или .js/.ts, предпросмотр, открытие несохранённого черновика. Синтаксический парсер Acorn проверяет разрешённые AST-узлы; код не исполняется. UUID назначаются при переносе, существующие кейсы не заменяются. Проверены повторные типы, цепочки, escape-последовательности, ошибки с позициями, лимиты, отсутствие записи до сохранения, защита выхода, сохранение и повторное открытие. Импорт нескольких кейсов, приватный Git и выполнение шагов не входят в реализацию.
