# Общий каталог действий пульта

Статус: реализовано и проверено автоматическими тестами. LG — repeat стрелок и громкости; Samsung — native UP/DOWN/LEFT/RIGHT/VOLUME_UP/VOLUME_DOWN. На физическом Samsung подтверждён RIGHT; остальные пять кнопок ещё требуют проверки на ТВ.

## Цель и границы

Единый каталог для существующего пульта, будущей записи действий и BDD-сценариев. Первые платформы — LG webOS и Samsung Tizen; новые платформы подключаются адаптерами. Все текущие кнопки сохраняются. В объём входит нативное зажатие для имитации физического пульта. Существующие обычные команды и операции питания сохраняются; для удержания потребуется отдельное расширение контракта.

## Проверенная исходная реализация до изменений

- `packages/contracts/src/tv-command.ts` определяет 26 обычных кнопок, отдельно — запуск Wink.
- `apps/web/src/pages/Remote.tsx` содержит подписи, группы, клавиатурные привязки и список повторяемых кнопок.
- Удержание стрелок и громкости сейчас означает повтор обычных команд: первая сразу, повтор через 400 мс, затем каждые 200 мс. Занятые интервалы пропускаются без очереди.
- Питание выполняется отдельно через PowerControls и операции питания; запуск Wink — через поиск и запуск приложения. Это не обычные протокольные кнопки.
- Адаптеры принимают обычное нажатие через `sendButton`. Нативное удержание через отдельные press/release этим интерфейсом не предоставляется.

## Выбранный подход

Расширить существующий пакет contracts общим каталогом метаданных, сохранив текущие идентификаторы обычных кнопок. Не переносить протокольные коды в каталог и не вводить параллельный универсальный исполнитель: перевод команд остаётся в адаптерах, питание — в существующем механизме питания.

Альтернативы: каталог только в UI не подходит будущему исполнителю сценариев; полная замена протокола команд сейчас неоправданно расширяет объём и риск изменений.

## Состав каталога

Для действия задаются стабильный идентификатор, подпись, группа, вид исполнения (кнопка, приложение, питание), клавиатурные привязки и режим удержания. Иконки и геометрия остаются в веб-интерфейсе.

Обязательны: UP, DOWN, LEFT, RIGHT, ENTER, BACK, HOME, VOLUME_UP, VOLUME_DOWN, MUTE, цифры 0–9, CHANNEL_DOWN, CHANNEL_UP, RED, GREEN, YELLOW, BLUE, Wink и питание — всего 28 действий текущего пульта.

Питание представлено как элемент каталога, но не превращается в безусловный toggle для сценариев: будущий исполнитель должен различать намерение включить и выключить и сохранять существующие проверки и подтверждение выключения.

## Удержание

Целевое действие: нажатие → удержание → отпускание. Для LG пользователь согласовал режим `repeat` только для стрелок и громкости: первая команда сразу, повтор через 400 мс, затем каждые 200 мс, без очереди. Для Samsung применяется `native` через Press/Release на поддерживаемых кнопках. Остальные действия имеют режим `none`, если поддержка отдельно не подтверждена. Повтор не эквивалентен нативному зажатию: режим явно присутствует в каталоге и будущей записи.

Удержание получает серверного владельца, привязку к конкретному ТВ и авторизованной сессии, идентификатор операции и ограниченный срок жизни. Отпускание должно быть идемпотентным и не блокироваться обычным busy-гейтом удержания. Отмена указателя, потеря фокуса, скрытие страницы, закрытие экрана, отзыв сессии и истечение срока инициируют освобождение кнопки. При потере транспорта нельзя обещать доставленное отпускание: результат остаётся явно неопределённым, а восстановление не должно повторно нажимать кнопку.

Для будущей записи требуется сохранять режим и длительность удержания. Сам формат записи и выполнение сценариев не входят в этот этап. Запуск Wink является действием приложения, а не физической клавишей; нативное удержание для него не заявляется. Долгое нажатие питания может иметь отдельные последствия и требует отдельной проверки и явного согласования, без обхода существующего подтверждения выключения.

Для Samsung пользователь подтвердил результат отдельного теста RIGHT: Press, удержание одну секунду, Release; движение и остановка работают. Это не подтверждает все остальные кнопки. Для LG поиск нативного способа больше не блокирует реализацию согласованного repeat. Новые проверки на физическом ТВ проводятся только после согласования кнопки и длительности.

## Расширение платформ

### Исследование транспорта

- Samsung: в исходниках [samsungtvws](https://github.com/xchwarze/samsung-tv-ws-api/blob/master/samsungtvws/remote.py) реализованы отдельные `Cmd: Press` и `Cmd: Release` с тем же ключом. Это подтверждение формы пакетов, но ещё не проверка поведения конкретного ТВ и каждой кнопки.
- LG: [Connect SDK MouseSocket](https://github.com/ConnectSDK/Connect-SDK-Android-Core/blob/master/src/com/connectsdk/service/webos/WebOSTVMouseSocketConnection.java) отправляет `type:button` и `name`, без отдельного отпускания. Параметр `down` у `type:move` относится к перетаскиванию указателя, его нельзя считать доказательством зажатия клавиши.
- Найденный [magic_mapper](https://github.com/andrewfraley/magic_mapper) работает с input-устройствами на самом ТВ и требует root. Это вне текущего решения; root не предлагается как обязательное условие приложения.
- Вывод: транспорт нативного удержания Samsung имеет подтверждённую реализацию; для LG через используемый сетевой протокол способ пока не найден. Это не доказательство невозможности. Неизвестные поля пакетов не отправляются на физический ТВ без отдельного согласованного эксперимента.

Каталог описывает намерения, адаптер — их реализацию. Статическая запись действия не гарантирует доступность на конкретном ТВ: существующие runtime-проверки подключения, кнопок, приложений и питания остаются обязательными. Состояние пульта дополнительно сообщает поддерживаемые нативно удерживаемые кнопки; отсутствие этого поля означает отсутствие нативной поддержки.

Платформенные расширения должны иметь отдельные идентификаторы и явно объявленную поддержку; нельзя молча заменять неподдерживаемое действие похожей командой. При добавлении новой платформы нужны её отображения и проверки возможностей, а не копия каталога.

## Проверка и критерии приёмки

- Каталог содержит все 28 действий без дубликатов; обычные кнопки полностью соответствуют существующей схеме.
- UI берёт подписи, группы, клавиатурные привязки и возможности удержания из каталога, не дублируя правила.
- Существующие команды и маршруты питания/Wink не меняются; кнопки не пропадают и не меняют расположение.
- Детерминированные тесты проверяют порядок press/release, гонку отпускания до завершения нажатия, дубли отпускания, изоляцию ТВ и сессий, отмену, таймаут и потерю транспорта. Нативное удержание Samsung не создаёт поток Click-команд; repeat LG сохраняет согласованные интервалы и пропускает занятые интервалы.
- Неповторяемые действия, особенно питание и Wink, не приобретают повтор при зажатии.
- Проверяются текущие тесты пульта, контрактов, типы и браузерная геометрия. Команды физическим ТВ автоматически не отправляются.

## Не входит в этап

Импорт BDD, редактор, запись, камера, удалённый доступ и новые кнопки. Каталог подготавливает их интеграцию, но не подменяет отдельные спецификации этих возможностей.
