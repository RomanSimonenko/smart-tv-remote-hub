# OCR-проверка условий шага

Дата: 2026-10-18. Статус: проект на проверку перед реализацией.

## Цель и согласованные правила

Проверять результат шага по наличию заданных надписей на экране телевизора.
Например, для «Тогда Пользователь попадает на страницу Профиля» задать две
обязательные надписи: «Мое кино», «Мои подписки».
Все надписи найдены на одном снимке — проверка пройдена. Хотя бы одна не найдена,
включая пустой результат успешно выполненного OCR, — шаг и тест провалены,
следующие команды не отправляются. Ошибка OCR — техническая ошибка запуска,
а не отрицательный результат проверки и не успех.

Сравнение изображений отложено. Повторных кадров, ожидания появления текста,
повторных OCR-попыток и дополнительной паузы нет.

## Паузы и момент проверки

Фактическая текущая модель: `pauseAfterMs` принадлежит каждому нажатию;
отдельной паузы шага нет (`packages/contracts/src/test-cases.ts`).
Раннер после каждого нажатия выдерживает его паузу и сохраняет свежий снимок
(`apps/web/src/run-execution.ts`). Это поведение сохраняется.

Условия проверяются только по последнему снимку шага, после паузы последнего
нажатия. Других снимков для OCR не делаем. Шаг без нажатий сразу получает один
свежий снимок и проверяется без дополнительной задержки. Если ожидание нужно
после перехода, его задаёт существующая пауза у нажатия, вызвавшего переход.

## Предлагаемый интерфейс и данные

В существующем редакторе шага добавить блок «Условия» после нажатий.
Один тип условия на этом этапе: «На экране есть текст». Пользователь добавляет
надписи отдельными строками и может удалить каждую из них. Все строки обязательны.
Условия доступны для любого типа шага; текст Дано / Когда / Тогда не исполняется
и не преобразуется в условия автоматически.

Предлагаемые ограничения: не более 20 надписей на шаг, от 1 до 200 символов
на надпись после удаления внешних пробелов. Пустая добавленная строка блокирует
сохранение шага с конкретной ошибкой. Отсутствие условий сохраняет старое поведение.
Условия применяются кнопкой сохранения шага, затем сохраняются вместе с кейсом;
несохранённые условия учитываются существующей защитой выхода.

Хранить необязательный список `textConditions` вместе со шагом и снимком версии
кейса в запуске. Валидация и правила сравнения едины для всех потребителей.
Старые кейсы и запуски без этого поля продолжают читаться без изменений.

## Предлагаемые правила поиска

Искать по всему выровненному экрану. В первой версии поддержать русский и английский
текст без выбора области. До сравнения привести Unicode к NFC, игнорировать регистр,
заменить последовательности пробельных символов одним пробелом и убрать внешние
пробелы. Буквы «е» и «ё», знаки препинания и разные алфавиты не подменять.
Нечёткий поиск и исправление OCR-опечаток не применять.

Искомая надпись должна совпасть с непрерывной последовательностью распознанных слов,
а не с частью более длинного слова. Не соединять текст из разных несвязанных блоков
экрана для получения ложного совпадения. Исходный распознанный текст сохраняется
для объяснения результата; нормализация не меняет пользовательское ожидание.

## Выполнение и владение результатом

Сервер проверяет условия по сохранённому снимку последнего действия шага и
зафиксированной версии кейса. Браузер не передаёт готовый вердикт. До завершения
проверки сервер не разрешает переход к следующему шагу и не завершает тест.
Снимок остаётся свидетельством независимо от результата распознавания.

OCR выполняется локально: изображения не отправляются внешним сервисам.
Использовать отдельный ограниченный исполнитель с отменой и техническим тайм-аутом;
тайм-аут не означает повторную попытку и не добавляет ожидания появления надписей.
Проверку связать с запуском, шагом и хешем сохранённого снимка. Повторный запрос
не запускает вторую параллельную проверку и не меняет зафиксированный результат.
При остановке, отзыве сессии или завершении приложения OCR отменяется; поздний
ответ не переводит остановленный запуск в успешный.

После дополнительных проверок 2026-10-19 выбран PaddleOCR 3.2.0 /
PaddlePaddle 3.2.0: PP-OCRv5_mobile_det + eslav_PP-OCRv5_mobile_rec,
4 CPU-потока, MKL-DNN выключен. Модели поставляются при сборке и проверяются
по контрольным суммам; сохраняется отдельный процесс и технический тайм-аут
30 секунд. Первоначально использовавшийся Tesseract заменяется без изменения
правил сравнения. Основание: [проверка движка](../../design/reviews/2026-10-18-ocr-runtime.md).
Для ненайденных условий допустима адресная перепроверка до трёх областей:
совпадение всей строки без пробелов служит только выбором кандидата. Повторный
TextRecognition с входом [3,48,640] выполняется без детектора, один раз на
область, с сохранением основного текста. Успех определяется только существующим
строгим matcher; общий технический тайм-аут и отмена охватывают оба этапа.
Маркер +line-retry-640 в модели фиксирует использование второго прохода.
Уточнение 2026-10-19: модели сохраняются в одном процессе после первого
успешного запроса, включая адресный распознаватель, если он понадобился.
Кадры и результаты принадлежат отдельным запросам с идентификаторами.
После отмены, тайм-аута или аварии процесс завершается и создаётся заново
при следующем запросе. Срок 30 секунд считается для каждого запроса отдельно,
включая загрузку моделей в холодном процессе. Одновременная работа запрещена.

Смена движка не меняет контракт условий; автоматического переключения нет.
Экспериментальный код не переносится целиком.

## Вердикты и совместимость

Для каждого проверяемого шага хранить результат каждой надписи, общий результат,
время проверки и идентификатор движка/моделей. Не смешивать результат OCR с доставкой
команды, фазой сохранения снимка или технической ошибкой.

Предлагаемые итоговые статусы: `passed` — все шаги завершены и все настроенные
условия пройдены; `failed` — хотя бы одно условие не выполнено; `needs_review` —
в кейсе нет условий и сохранены все снимки. Существующие `stopped` и `error`
сохраняют смысл. Шаги без условий обозначаются «Выполнен без автоматической
проверки», а не «Проверка пройдена». В отчёте успешного запуска явно показывать
покрытие: сколько шагов имеют условия. Исторические запуски не пересчитываются.

## Отчёт и безопасность

В раннере и отчёте отображать «Проверяем текст», результат каждого условия,
ожидаемую надпись, найдено/не найдено и соответствующий снимок. При провале
показывать отсутствующие надписи; последующие шаги — «Не выполнялся».
Технические ошибки распознавания показывать отдельно с причиной.
История поддерживает новые итоговые статусы через общие компоненты.

Условия, OCR-текст и снимки наследуют доступ и сроки хранения запуска. Не писать
их в общие серверные журналы, публичные фикстуры или документацию. Для проверок
использовать синтетические экраны; реальные команды ТВ требуют отдельного
разрешения. Текущий интерфейс использует общие токены и композицию проекта.

## Проверка реализации

- Контракты: старые записи, ограничения, пустые/некорректные условия.
- Сравнение: русский/английский, регистр, пробелы, е/ё, границы слов,
  несвязанные блоки, все/часть/ни одной найденной надписи.
- Раннер: проверка только последнего снимка; существующие паузы; шаг без
  нажатий; отсутствие повторных кадров; запрет следующей команды при провале.
- Жизненный цикл: отмена, технический тайм-аут, поздний ответ, повторный запрос,
  потеря связи, ошибка хранения и перезапуск во время проверки.
- Полный путь: сохранение условий → версия кейса → снимок → OCR → результат
  шага → итог запуска → история и отчёт после перезагрузки.
- Синтетический Docker и браузер: положительный/отрицательный результат,
  техническая ошибка, старый кейс без условий, защита несохранённых правок.
- После UI-изменений: обновить активное Docker-приложение с сохранением данных,
  проверить отрисовку во встроенном браузере, не отправляя команды ТВ.
