# Рабочая база выделения экрана в видео

Статус: вариант отдельной live-пробы 960×540 принят пользователем как рабочий 2026-10-17 после проверки повышения разрешения. Он выбран по умолчанию при запуске сервера. Это не разрешение на интеграцию в рабочий раннер.

Принятый режим: вход для обработки до 1280×720, превью 960×540; поиск в 640 с запасными 800/960 только при отсутствии геометрии. Неоднозначность не обходится сменой масштаба. Четыре стороны подтверждаются свежими краями; граница сопровождается локальным поиском с проверкой полярности контраста. Вложенная граница проверяется существующим анализом рамки. При потере результат скрывается; повторный захват не должен подменять установленную внутреннюю границу одиночным внешним контуром.

Проверки: синтетические движение, разрывы сторон, потеря, внешняя рамка после потери и восстановление; 61 тест пакета прошёл. В последней реальной серии после движения камеры: 423 из 425 кадров показаны, отказов нет, около 9 обновлений/с. Это короткий замер, не гарантия для любых условий. Начальный одиночный контур может включать рамку; похожее окно остаётся известным ложным обнаружением.

Снимок исходников рабочей базы сохранён локально в `.local/screen-experiment/video-baseline-640/probe-source.tar.gz`. Реальные изображения не входят в документацию и публичные fixtures.

Проверка 960×540: 423 из 438 кадров показаны, 13 отказов, два подтверждения, около 4,8 обновления/с. Последние 239 кадров этой серии показаны без новых отказов; внутренняя граница сохраняется. Это последовательный короткий замер, не контролируемое сравнение производительности. Повышение разрешения принято с этим компромиссом по скорости. 62 теста пакета, сборка и проверка типов прошли.

Режим 640×360 остаётся запасным: `startLiveProbe(0, {livePreviewWidth:640})`, вход до 960×540. Исходники принятого режима 960×540 сохранены локально в `.local/screen-experiment/video-baseline-960/probe-source.tar.gz`. OCR и сравнение снимков отложены по запросу пользователя.

Уточнение обрезки по запросу пользователя: live-выход имеет отступ 0,3% внутрь с каждой стороны в выровненных координатах. Отступ применяется в преобразовании перспективы и не меняет измеренные углы, поиск или сопровождение. Разрешение выхода сохраняется; статические снимки не меняются. На реальном кадре webOS 2026-10-18 тонкие полосы физической рамки визуально не обнаружены. Это проверка текущего ракурса, а не гарантия для всех положений камеры.
