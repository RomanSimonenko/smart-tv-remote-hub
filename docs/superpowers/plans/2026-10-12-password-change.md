# Password Change Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Владелец меняет пароль, сохраняя доступ в текущем браузере и завершая остальные сессии.

**Architecture:** Общая политика пароля в contracts; атомарная смена credentials и сессий в OwnerRepository; оркестрация проверки и отзыва ресурсов в AuthSessionService. App владеет обновлённым CSRF, профиль показывает форму через существующий диалог.

**Tech Stack:** TypeScript, Zod, Fastify, SQLite, React, Vitest, Playwright. Без новых зависимостей.

**Spec:** ../specs/2026-10-12-password-change-design.md

## Global Constraints
- Пароль 6–128 Unicode code points; пробелы не обрезаются; существующие хеши сохраняются.
- Текущий пароль обязателен; новый cookie и CSRF заменяют старые. Остальные сессии недействительны.
- Секреты не логируются, не сохраняются в браузере, не попадают в снимки.
- Интерфейс по дизайн-ТЗ; палитра и компоненты общие; подсказка о длине постоянно видима.
- Реальный пароль установки и физические телевизоры в проверках не используются.
- Существующие незакоммиченные изменения сохраняются. Публикация и коммит всего рабочего дерева не входят в этап.

## Review Focus
- Вход по старому паролю, начатый до смены, не создаёт действующую сессию после неё.
- Две смены и logout во время хеширования не обходят повторную проверку credentials/сессии.
- Ошибка очистки одного ресурса не мешает отзыву остальных и не теряет новую cookie.
- Потеря ответа не приводит к автоматической повторной смене или ложному сообщению об успехе.
- Другие вкладки с обновлённой cookie, но старым CSRF могут восстановить состояние сессии.

- [x] Транзакцией повторно сверять credentials и активность текущей сессии, менять хеш, удалять прежние сессии, вставлять новую; сохранять прежние данные при отказе.
- [x] Защитить вход от гонки смены пароля через атомарную сверку ожидаемого хеша при создании сессии.
- [x] Добавить AuthSessionService.changePassword(token, currentPassword, newPassword), типизированный отказ и результат с новым token/identity/cleanupWarning.
- [x] Учесть в памяти все активные токены, замеченные authenticate/login; хранить только до срока действия или отзыва. Отзыв уведомляет всех существующих подписчиков и очищает учёт.
- [x] Подключить существующий механизм очистки onRevoke для всех старых токенов; новая сессия уже существует до очистки. Сбой очистки диагностируется без секретов и даёт cleanupWarning.

## Результат
Реализовано без коммита и публикации. Проверки: полный pnpm test — 1400 до последнего исправления фокуса; после него весь web — 366 (было 365), остальные 1035 тестов не затронуты. Build/typecheck и diff check прошли. Общий браузерный запуск: 75 успешных, один устаревший ожидаемый текст о минимуме 12; после обновления ожидания и исправления фокуса все 37 затронутых браузерных сценариев прошли.
Независимое ревью выявило два случая: ошибка освобождения удержания не доходила до результата и ответ proxy 5xx не считался неопределённым. Оба воспроизведены, исправлены и повторно проверены. Дополнительно исправлено восстановление фокуса при размонтировании открытого диалога.
