# Профиль владельца — план реализации

> Выполнять последовательно в этом чате по `superpowers:executing-plans`, без делегирования. План согласован пользователем 2026-10-12.

**Цель:** рабочий профиль с именем и 16 готовыми иконками, сохранённый на сервере.

**Архитектура:** строгие общие контракты; SQLite хранит профиль владельца; отдельные защищённые маршруты читают и изменяют профиль. Web получает сохранённый профиль через единый hook и использует его в меню и форме. Home сохраняет владение навигацией и блокировками ТВ.

**Стек:** существующие React/TypeScript, Zod, Fastify, SQLite, Tabler, Vitest и Playwright; без новых зависимостей.

**ТЗ:** [Профиль владельца](../specs/2026-10-12-owner-profile-design.md), согласовано пользователем.

## Ограничения

- Русский интерфейс, тёмная тема; темы и RU/EN — финальный этап.
- Логин неизменяемый; пароли и сессии не меняются; фото не загружаются.
- Имя: trim, 1–64 Unicode code points; иконка: фиксированный идентификатор или null.
- Только синтетические данные в тестах и снимках; физических ТВ не касаться.
- API сессии и входа сохраняют существующие ответы.
- Меню 224/72 px; доступность и модальные блокировки сохраняются.

## Особое внимание

1. Старой базе не нужен повторный setup: имя берётся из логина, иконка — инициалы.
2. Ошибка сохранения оставляет черновик; меню показывает последнее подтверждённое значение.
3. Истекшая сессия запускает существующий выход; запоздалый ответ не восстанавливает профиль после выхода.
4. Уход из формы с изменениями требует подтверждения, включая выход из приложения.
5. Переход с удерживаемой клавиши прекращает повторение и освобождает камеру; диалог подтверждения питания нельзя обойти.
