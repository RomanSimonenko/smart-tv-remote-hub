# Проверка технологии автоматической оценки экрана

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Выполнение:** завершено 2026-10-14; исторические результаты и снимки архивированы локально.

**Goal:** Получить измеряемые результаты OCR и сравнения изображений до интеграции в редактор и раннер.

**Architecture:** Изолированный локальный исследовательский инструмент принимает изображения из каталога и описание проверок, выполняет OCR и поиск эталона, сохраняет отчёт. Он не управляет ТВ, не изменяет пользовательские кейсы и не добавляет рабочие кнопки в приложение. Результат этапа — воспроизводимый эксперимент и решение о пригодности технологии, а не готовый раннер.

**Tech Stack:** Node.js, отдельный workspace-пакет TypeScript/Vitest; Tesseract.js как проверяемый кандидат OCR. Базовый поиск эталона — нормализованная корреляция яркости через OpenCV.js; это кандидат, а не окончательный алгоритм продукта.

**Spec:** [Согласованный подход](../specs/2026-10-14-visual-checks-design.md).

## Global Constraints

- Импортированный код не выполняется; реальные сценарии не публикуются.
- Генеративный ИИ и внешняя обработка кадров не используются.
- Рабочие зависимости и данные OCR предварительно загружаются; сам эксперимент работает без сети.
- Исходный кадр сохраняется отдельно от разметки результата.
- Ошибка распознавания не подтверждает отсутствие текста; неопределённость видна в отчёте.
- Ни приложение, ни Docker, ни физический телевизор на этом этапе не меняются.

## Review Focus

- Пустой или повреждённый файл приводит к явной ошибке, а не успешной отрицательной проверке.
- Размытый кадр и мелкий текст не должны ошибочно подтверждать отсутствие строки.
- Сходные изображения с разным фокусом необходимо различать по эталону.
- Отмена, ошибка и повторный запуск не оставляют OCR worker работающим.
- Публикуемые материалы синтетические; реальные кадры остаются в игнорируемом локальном каталоге.

## Границы и файлы

Создать пакет `tools/visual-checks-probe/` с собственными `package.json` и `tsconfig.json`
по установленным workspace-соглашениям. Перед установкой проверить актуальные
официальные API и лицензии Tesseract.js/OpenCV.js, закрепить выбранные версии.
Не использовать CDN во время оценки кадров.

Вход: каталог кадров и JSON-манифест с относительными путями к изображениям,
нормализованной областью `{x,y,width,height}` в диапазоне 0–1, языком OCR,
ожидаемой строкой/эталоном и меткой ожидаемого наблюдения.
Входные кадры этого этапа уже содержат экран ТВ: автоматическое определение его
границ — отдельный этап, не скрытая возможность исследовательского инструмента.

### Task 2: OCR и явное сравнение

**Files:** `tools/visual-checks-probe/src/ocr.ts`, `src/text-check.ts`, `src/text-check.test.ts`, `src/ocr.test.ts`.

**Interfaces:** `recognizeText(imagePath: string, region: Region, language: 'rus'|'eng'|'rus+eng', signal: AbortSignal): Promise<OcrObservation>`; наблюдение содержит текст, координаты и confidence, отдельно — ошибку выполнения. `compareText(actual: string, expected: string, operator: 'equals'|'contains'|'notContains'): boolean` выполняет точное сравнение; нормализация на этапе эксперимента отсутствует.

- [x] Добавить тесты `exact_text_comparison`, `empty_ocr_is_not_absence_evidence`, `ocr_failure_is_explicit`, `worker_is_released_on_abort`; проверить падение до реализации.
- [x] Реализовать адаптер Tesseract.js с локальными моделями, ограничением области, явной отменой и освобождением worker в каждом пути завершения.
- [x] Запустить тесты и OCR по синтетическому набору. Сохранить ошибки распознавания и время каждого вызова; confidence не считать доказательством качества кадра.
- [x] Отрицательное условие без проверенного критерия пригодности возвращает `inconclusive`, даже если строка не найдена.

### Task 3: Сравнение с эталоном

**Files:** `tools/visual-checks-probe/src/image-check.ts`, `src/image-check.test.ts`.

**Interfaces:** `compareImage(imagePath: string, referencePath: string, region: Region): Promise<ImageObservation>` возвращает численную оценку корреляции и координаты лучшего совпадения либо явную ошибку. Порог передаётся в описании эксперимента, не скрывается внутри алгоритма.

- [x] Добавить тесты `reference_is_found`, `different_focus_is_measured`, `invalid_region_is_rejected`, `uniform_reference_is_rejected`; подтвердить падение.
- [x] Реализовать поиск эталона OpenCV.js в ограниченной области без неявного изменения масштаба. Проверить границы области и размеры эталона; освободить выделенные матрицы при успехе и ошибке.
- [x] Запустить тесты и измерить оценки для совпадений/несовпадений при искажениях. Не объявлять произвольный порог пригодным до анализа пересечения распределений.

## Следующие этапы после эксперимента

1. Локальная проверка на реальных кадрах и автоматическое обнаружение/нормализация экрана; отдельное согласование критериев пригодности и отрицательных условий.
2. Макеты и детальное ТЗ настройки проверки в редакторе, хранение эталонов и совместимое расширение схемы кейса.
3. ТЗ раннера: действия, исключительное управление ТВ, ожидание проверок, отмена и сохранение доказательств.
4. Реализация и E2E, сверка с дизайн-ТЗ/макетами и проверка Docker-приложения.

Каждый этап получает собственный план: текущий документ не разрешает обходить
неопределённые контракты раннера или считать его реализованным.
