# Общая оболочка интерфейса — план реализации

Дата: 2026-10-11. Статус: подготовлен к реализации после слияния ТЗ дизайна.

> Для исполнителя: выполнять последовательно в этом чате по `superpowers:executing-plans`, без делегирования. Каждый шаг завершается проверкой; изменения пульта не смешивать с изменением его протокола.

**Цель:** перенести работающие экраны списка, добавления и управления ТВ в единую оболочку согласованного дизайна.

**Архитектура:** существующие `Home`, `Dashboard`, `TvSetup`, `Remote` сохраняют владение устройствами, операциями и запросами. Общая оболочка отвечает за меню, компоновку и предпочтения браузера. Рефакторинг не вводит новый роутер или транспорт.

**Стек:** React, TypeScript, CSS custom properties, существующая `@tabler/icons-react`, Vitest/Testing Library и Playwright.

**Спецификация:** [ТЗ дизайна](../specs/2026-10-11-product-ui-design.md).

## Границы первого PR

Включены: общие токены тёмной темы, базовые поверхности/контролы, боковое меню с сохранением свёрнутости, перенос работающих экранов ТВ, сохранение выхода/настроек ТВ/помощи клавиатуры и их блокировок.

Не включены в первый PR: редактор, раннер, фиктивные результаты, новый дашборд аналитики, автоопределение границ камеры, удалённый агент, фото профиля. Светлая тема и полный русский/английский перевод идут следующим самостоятельным PR: частичный перевод не представляется готовой поддержкой языка.

Пункты будущих разделов не открывают страницы с выдуманными данными: они видны как недоступные с пояснением. Рабочий раздел — «Телевизоры». Настройки ТВ остаются отдельным действием устройства; общие настройки и профиль не подменяются им.

## Общие ограничения

- Меню 224 px / 72 px, у левого края, одинаковые иконки и порядок из ТЗ.
- Все значения палитры из раздела 4 ТЗ; семантические переменные вместо новых локальных цветов.
- Существующая раскладка пульта, удержание кнопок, pointer capture, запрет команд за диалогом и очистка камеры сохраняются.
- Перемещение раздела не отправляет команды и не меняет выбор ТВ незаметно.
- Применять реальные имя пользователя и возможности платформы; не подставлять демонстрационные значения из макета.
- Предпочтения не хранят сценарии, доступы, адреса ТВ или секреты.
- Не добавлять зависимостей без необходимости. Все проверки используют синтетические устройства.

## Особое внимание при проверке

1. Сохранённое значение свёрнутости повреждено или хранилище браузера недоступно: меню остаётся работоспособным с явным непостоянным состоянием.
2. Смена экрана во время удержания: повторение прекращается, команда не переходит на другой ТВ.
3. Открытый диалог/подтверждение питания: меню не обходит существующую блокировку взаимодействий.
4. Узкое окно, масштаб 200%, длинное имя: контент не перекрыт фиксированным меню, элементы доступны.
5. Истекшая сессия и неуспешный logout: существующие остановка запросов и восстановление состояния не ломаются.
