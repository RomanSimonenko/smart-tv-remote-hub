# Step Key Sequences Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Добавлять несколько нажатий через существующий пульт и сохранять их в шаге.

**Architecture:** Общий контракт описывает действия шага и ограничения. Существующая визуальная раскладка пульта отделяется от сетевого контроллера и переиспользуется в диалоге набора. SQLite сохраняет расширенный steps_json без миграции таблицы.

**Tech Stack:** TypeScript, React, Zod, Vitest, Testing Library, существующий SQLite и Docker. Новых зависимостей нет.

**Spec:** [Согласованное ТЗ](../specs/2026-10-15-step-key-sequences-design.md).

## Global Constraints

- Максимум 200 нажатий на шаг; pauseAfterMs — целое 0–60000, начальное 500.
- Тип given/when/then и описание независимы от исполнения.
- Настройка не отправляет команды ТВ. Пульт сохраняет существующие кнопки/иконки/порядок.
- «Готово» атомарно добавляет локальный набор; отмена/Escape/крестик отбрасывают его.
- Старые кейсы и импорт остаются описательными, без автоматического назначения команд.
- OCR, раннер, снимки и отчёт — последующий отдельный этап; здесь нет ложного рабочего запуска.
- Защита несохранённых правок, версия и общая палитра сохраняются.

## Review Focus

- Лимит учитывает сохранённые и ещё не применённые действия; после удаления место освобождается (задача 3).
- Отмена диалога не удаляет ранее настроенные действия, Escape не добавляет BACK (задача 3).
- Выбор и перемещение другого шага не теряют его неприменённую последовательность (задача 3).
- Чтение старого кейса не меняет версию и идемпотентное повторное создание (задача 1).
- Извлечение пульта не ломает удержание, подавление клика и клавиатуру живого управления (задача 2).

## Self-review

Три задачи покрывают первый этап ТЗ: контракт, переиспользование пульта, редактор.
Будущая последовательность команда → пауза → кадр описана в ТЗ, но её раннер
намеренно не включён в этот план. Паузы/лимиты имеют общий источник, старые данные
не нормализуются при чтении, сохранение JSON не требует миграции таблицы.
