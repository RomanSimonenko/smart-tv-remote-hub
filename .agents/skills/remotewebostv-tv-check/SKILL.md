# Проверка на телевизоре

Разделяй состояние приложения, доставку команды и наблюдаемый результат
на физическом экране. Корневой `AGENTS.md` задаёт общие правила;
этот навык помогает выбрать проверки конкретной платформы.
Все пути ниже заданы от корня репозитория.

## Выбери проверку

1. Установи активный checkout/runtime, выбранный `tvId`, платформу и модель.
   Адреса и ключи получай из существующей конфигурации без вывода в чат,
   исходники и тестовые fixtures. Работающий контейнер может отставать
   от текущего кода.
2. Сформулируй наблюдаемый симптом и минимальную проверку. При диагностике
   ошибки или изменении кода сначала используй подходящий синтетический
   тест владельца поведения: пакет адаптера, сервис API или frontend.
   Простое информационное чтение не требует запуска тестов.
   Для изменения формата ответа прочитай
   настоящий producer и безопасную проекцию реального ответа.
3. Информационные чтения выполняй в рамках запроса. Для сопряжения,
   питания/WOL, нажатий и запуска реального кейса проверь конкретное
   разрешение в текущей беседе; используй уже данное, не спрашивай повторно.
   Само подключение рабочего экрана может вызвать автоматический reconnect:
   проверь его поведение перед открытием неизвестного состояния.

## Особенности платформ

| Платформа | Где смотреть | Что различать |
|---|---|---|
| LG webOS | `packages/webos`; `docs/compatibility/lg-43up76906le-webos-6.5.3.md` | SSAP/hello metadata и версия прошивки — разные источники. WOL из Docker Desktop требует проверки доставки в LAN и наблюдения ТВ. |
| Samsung Tizen | `packages/tizen`; `apps/api/test/tv-platform-version.test.ts` | Remote WebSocket и SDB capability решают разные задачи. Версия ОС берётся из подтверждённых metadata, не из модели или версии remote API. Сохранённая версия offline — последнее известное значение, не свежая проверка. |
| Philips Whale OS | `packages/philips`; `docs/superpowers/specs/2026-10-20-philips-whale-design.md` | jointSPACE API version, firmware и Whale OS version не взаимозаменяемы. `/system` может содержать зашифрованные поля; используй существующий parser. HTTP 200 сам по себе не подтверждает успех pairing/key. |

Эти документы содержат результаты конкретных проверок, а не гарантию
совместимости всех моделей. Текущие capabilities и парсеры проверь в коде.
Если API не сообщает версию ОС, обозначь отсутствие. Подтверждённое
пользователем значение можно сохранить в рамках разрешённой задачи через
каноническое хранилище; объясни его происхождение. Не создавай таблицу
«модель → версия ОС» и не подставляй номер прошивки/API.

## Физическая проверка и вывод

- Выполни только согласованное минимальное действие, один раз. При
  неизвестном результате не повторяй автоматически потенциально
  неидемпотентную команду, особенно переключение питания.
- Проверь полный путь: запрос → выбранный адаптер → подтверждение
  транспорта → статус API → экран/подтверждение пользователя.
  Успешная отправка WOL или клавиши не доказывает изменение экрана.
- Для камеры начни с синтетических проверок. Реальные кадры оставляй
  в приватном хранилище; геометрия и OCR не доказывают физическую
  идентичность ТВ. Не отправляй кадры во внешние сервисы без разрешения.
- Заверши временные чтения/подписки; не разрывай пользовательское
  рабочее соединение и не меняй настройки ТВ ради уборки.

Кратко сообщи: платформа и проверенное поведение, синтетические результаты,
что подтверждено транспортом, что видно на ТВ и что осталось непроверенным.
Если ТВ недоступен, продолжай независимые проверки и запроси только
необходимое действие пользователя; не выдавай заглушку за аппаратную проверку.
